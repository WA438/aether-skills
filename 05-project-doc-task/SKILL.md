# 项目文档与任务管理

## 一、任务状态分类（强制三态）

所有工作必须归入以下之一，禁止含糊：

| 标记 | 含义 |
|---|---|
| 【已完成】 | 已执行且验证通过，附证据 |
| 【待修复·待验证】 | 已改动但未验证，或未修复 |
| 【阻塞项】 | 因硬件/权限/信息缺失无法推进，需写明阻塞原因 |

## 二、任务清单格式

```markdown
## 任务：xxx

| # | 项目 | 状态 | 说明 |
|---|---|---|---|
| 1 | 网络固化 | 【已完成】 | 有线 .71 / 无线 .240，ip -brief 已确认 |
| 2 | SSH 迁移 | 【已完成】 | 端口 36000，密钥权限原样 |
| 3 | 宝塔安装 | 【待修复·待验证】 | 服务未启动，待查日志 |
| 4 | SD 卡驱动 | 【阻塞项】 | RST 引脚冲突，需改硬件 |
```

## 三、版本变更记录

每次代码/配置改动必须记录四要素：

```markdown
### v1.2 - 2026-09-29
| 改动位置 | 改动内容 | 风险 | 预期效果 |
|---|---|---|---|
| src/ui/menu.c:45 | 菜单改为单步滚动 | 低，仅 UI | 消除跳行 |
| /etc/ssh/sshd_config | Port 改 36000 | 中，可能锁死 | 端口统一 |
```

风险等级：低（仅显示/局部）/ 中（服务级，可回滚）/ 高（系统级、不可逆）。

## 四、项目汇总报告

用户要汇总时，**同时输出精简版与完整版**：

**精简版**（适合快速回顾）
```
一、目标
二、已完成（条目式，每条一行）
三、待修复 / 待验证
四、阻塞项
五、下一步
```

**完整版**（适合存档复盘）
- 背景与目标
- 详细执行过程（含关键命令与输出）
- 已完成清单 + 验证证据
- 待办与阻塞项（含原因分析）
- 版本变更记录
- 风险与注意事项
- 下一步建议

## 五、需求管理

用户的新增/修改需求，必须：
1. 原样记录，不得擅自增删功能
2. 标注需求变更时间与影响范围
3. 同步更新 Agent 行为约束（写入 SKILL.md 或自定义指令）

指令集变更时输出 diff，让用户确认后再生效。

## 六、输出规范

结构化排版，条目清晰；禁止抒情废话；区分事实与推测；无法确认的标"待确认"而非编造。
